# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

한국폴리텍대학 강서캠퍼스 사이버보안과 1학년 「웹콘텐츠 제작」 10주차 실습 프로젝트입니다.  
Open-Meteo 공개 HTTPS API를 연동하여 전 세계 실시간 기상 관측 데이터, 한국 환경부 기준 미세먼지 지표, 24시간 기온 꺾은선 차트, 7일간 주간 예보 및 디바운스 검색 기능을 제공하는 반응형 스마트 기상 대시보드입니다.

---

## 🌤️ 소개

- **실시간 기상 관측**: 서울(강서), 서울(시청), 인천, 부산, 제주 등 주요 도시 및 전 세계 도시의 현재 기온, 체감 온도, 습도, 풍속, 강수량을 실시간 제공합니다.
- **한국 환경부 기준 미세먼지**: PM10(미세먼지)과 PM2.5(초미세먼지) 수치를 한국 환경부 4단계 기준(좋음/보통/나쁨/매우 나쁨) 컬러 뱃지 및 프로그레스 바로 직관적으로 시각화하고 맞춤형 행동 요령을 안내합니다.
- **24시간 시간별 기온 SVG 차트**: 외부 무거운 라이브러리 없이 순수 경량 SVG로 향후 24시간의 시간대별 기온 변화와 날씨 추이를 매끄러운 꺾은선 차트로 렌더링합니다.
- **7일간 주간 일기예보**: 향후 일주일간의 요일별 날씨 아이콘, 강수 확률(%), 최저~최고 기온 범위를 한눈에 파악할 수 있는 예보 카드를 제공합니다.
- **스마트 검색 & 자동완성**: 400ms 디바운스(Debounce) 처리가 적용된 전 세계 도시 검색창과 드롭다운 선택 기능을 지원합니다.

## 🌐 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo 기상 및 미세먼지 API의 특징**:
  Open-Meteo는 전 세계 국립기상청(NOAA, DWD, ECMWF, JMA 등)의 수치예보 모델 데이터를 통합하여 무료로 제공하는 오픈소스 기상 API입니다. 별도의 회원가입이나 API Key 발급이 필요 없으며, 전송 구간 암호화(HTTPS)를 표준으로 지원합니다.
- **UI 컴포넌트(`App.jsx`)와 API 통신 로직(`src/api/weather.js`) 분리 이유 (Decoupling)**:
  1. **관심사의 분리(Separation of Concerns)**: UI 화면 렌더링 로직과 네트워크 통신 및 데이터 가공 로직을 분리하여 코드의 가독성과 모듈성을 극대화했습니다.
  2. **유지보수성 및 확장성**: 향후 API 엔드포인트나 응답 스키마가 변경되더라도 UI 컴포넌트를 수정할 필요 없이 `weather.js` 모듈만 수정하면 되므로 변경의 파급 효과를 최소화할 수 있습니다.
  3. **예외 처리 및 보안 중앙화**: 네트워크 타임아웃, HTTP 오류, 지오코딩 실패 등 예외 처리(try/catch)를 통신 레이어에 중앙 집중화하여 안전성을 보장했습니다.
- **도시 검색 시 디바운스(Debounce, 400ms)의 필요성**:
  검색창에 사용자가 "Seoul"을 타이핑할 때 `S`, `e`, `o`, `u`, `l` 한 글자마다 즉시 API를 호출하면 순식간에 불필요한 네트워크 요청이 5회 이상 발생합니다. 이는 사용자 브라우저의 리소스를 낭비할 뿐만 아니라, API 서버 입장에서 DoS(서비스 거부) 공격과 같은 트래픽 부하를 유발하여 `429 Too Many Requests` 상태 코드와 함께 클라이언트 IP가 차단될 수 있습니다. 400ms 동안 추가 입력이 없을 때만 단 1회 검색 요청을 전송하도록 디바운스를 적용하여 API 남용을 방지했습니다.

## 🛡️ 보안에서 확인한 것 (사이버보안과 체크포인트)

- **공개 API(Public API) vs 비밀 키 API(Secret API)의 취급 원칙**:
  - Open-Meteo처럼 키가 필요 없는 완전 공개 API는 프론트엔드(React)에서 직접 안전하게 호출할 수 있습니다.
  - 하지만 유료 과금 API, 결제 모듈, 사내 회원 DB 접근 API 등 비밀 키(`Secret Key`)가 필요한 보안 API는 **절대로 React 프론트엔드 코드에 포함되어서는 안 됩니다.**
- **프론트엔드 직접 호출의 위험성과 백엔드 프록시(BFF, Backend For Frontend)의 필요성**:
  - 프론트엔드 소스코드나 `.env` 환경변수에 `API_SECRET_KEY`를 작성하더라도, 브라우저로 전송되는 순간 F12 개발자 도구의 Network 탭, 콘솔 메모리, 빌드된 `.js` 번들 파일에서 100% 평문으로 노출됩니다.
  - 키가 탈취되면 무단 API 호출로 인한 거액의 요금 청구, 계정 탈취, 고객 개인정보 유출 등 치명적인 보안 사고로 이어집니다.
  - 이를 방지하기 위해 클라이언트와 외부 API 사이에 **백엔드 프록시 서버(BFF)**를 구축해야 합니다. 프론트엔드는 자체 백엔드로 요청을 보내고, 백엔드 서버가 안전한 서버 환경변수(`process.env`)에 보관된 시크릿 키를 사용하여 외부 API와 통신한 뒤 결과만 프론트엔드로 중계해야 합니다.
- **HTTPS와 혼합 콘텐츠(Mixed Content) 방어**:
  - 배포 사이트가 `https://` 암호화 프로토콜을 사용할 때, 안전하지 않은 `http://` API 엔드포인트를 호출하면 브라우저 보안 정책에 의해 통신이 강제로 차단됩니다.
  - 평문 HTTP 통신은 중간자 공격(MITM, Man-in-the-Middle)을 통해 기상 데이터나 사용자 위치 정보가 도청되거나 악의적인 스크립트로 변조될 수 있기 때문에, 모든 외부 통신은 반드시 HTTPS 프로토콜을 사용해야 합니다.

## 🎨 커스터마이징한 부분

기본 요구사항 외에 완성도 높은 사용자 경험을 위해 **3가지 커스터마이징 기능(옵션 A + 옵션 B + 옵션 D)**을 직접 추가 구현했습니다:

1. **옵션 A: 날씨 및 낮/밤 기반 실시간 동적 비주얼 테마**
   - 현재 선택된 도시의 날씨 상태 코드(`weather_code`)와 낮/밤(`is_day`) 값을 분석하여 5대 테마 클래스(`theme-clear-day`, `theme-night`, `theme-rain`, `theme-cloudy`, `theme-snow`, `theme-thunder`)를 대시보드 전체에 동적으로 적용했습니다.
   - 낮에는 맑고 따뜻한 앰버/스카이블루 그라데이션, 밤에는 깊은 미드나이트 네이비, 비 오는 날에는 차분한 블루 그레이 톤으로 부드럽게 전환(`transition: background 0.8s ease`)되어 생생한 기상 현장감을 전달합니다.
2. **옵션 B: 최근 본 도시 LocalStorage 자동 저장 & 원클릭 재조회**
   - 검색창이나 프리셋을 통해 조회한 도시를 브라우저 `localStorage`에 자동으로 누적 저장(최대 5개, 중복 자동 제거)합니다.
   - 검색창 아래에 '⭐ 최근 본 도시' 칩 목록으로 배치하여 언제든 원클릭으로 해당 도시 기상 정보를 즉시 다시 확인할 수 있으며, 개별 삭제(`×`) 기능도 함께 제공합니다.
3. **옵션 D: 섭씨(°C) ↔ 화씨(°F) 실시간 단위 변환 토글**
   - 헤더 우측에 `[°C | °F]` 토글 스위치를 탑재하여, 버튼 클릭 한 번으로 현재 날씨 카드, 24시간 기온 차트, 7일간 주간 예보의 모든 온도 지표를 섭씨와 화씨로 실시간 변환하여 볼 수 있습니다.
